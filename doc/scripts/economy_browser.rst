Database browser snapshots
==========================

``resources/data-explorer/compare`` uses committed snapshots. Sphinx and
the visitor's browser never parse source databases or call the World Bank API.

The HTML build generates ``browser-index.json`` from those published snapshots.
It shares repeated recipe values, geography and correspondences, and stores
whole-economy GDP, value added and GHG totals for each native region/year. The
browser fetches individual reading files only for a sector selection. This
index is regenerated on every successful Sphinx HTML build; it adds no source
data and preserves missing indicators, tax bridges, emissions boundaries and
source terms. Do not edit the generated index or maintain a second copy.

For a local preview, serve the HTML build with gzip and conditional caching::

   python doc/scripts/serve_preview.py /tmp/mario-docs-build --port 8765

The server binds to loopback only. The existing private remote-preview proxy
can continue forwarding to the same address.

BONSAI uses a producer-only CO2/CH4/N2O subtotal on the explorer's
EDGAR-compatible AR5 GWP100 basis (1, 28 and 265; both methane origins use 28).
The same factors apply to its direct and life-cycle electricity observations.
Accelerated CO2 is excluded because its AR5 factor is unverified; F-gases are
not characterised. Supplied iLUC contributions to the selected gases remain
included, so inventory boundaries still differ from EDGAR. MARIO's BONSAI
default remains the official AR6 characterisation. The frozen AR6 equivalence
audit is retained separately from these recharacterised explorer indicators.

Refresh World Bank observations explicitly::

   python doc/scripts/fetch_world_bank.py --start 1990 --end 2025 \
     --output doc/source/_static/data/economy/world-bank.json

The current reference spans 1990–2025. Its 1990–1994 supplement preserves all
previously saved 1995–2025 observations and annual exchange rates;
``retrieval_batches`` records the retrieval date of each period.

Compute each database separately with the same parser/options as its walkthrough::

   python doc/scripts/build_economy_browser.py \
     --id exiobase-3112-2024-ixi --path /local/IOT_2024_ixi

Recipes live in ``doc/economy_browser.recipes.json``. The aggregation engine is
``doc/source/_static/reproduce/economy_browser.py`` (the internal snapshot engine).
Monetary scales, tax bridge, GHG row weights, source URLs and geography must be
explicit. The website's Python download is now a short MARIO-only starting
example generated by ``economy-model.js``. It does not embed the engine or a
World Bank snapshot, and does not claim to reproduce the finished CSV unaided.
Its comments identify remaining aggregation, filtering and conversion steps.
The GHG example weights rows from MARIO E/Ec directly: calc_ghg requires
uniform native units and rejects a different output unit, so it must not be
passed mixed kg / kg CO2e rows or requested tonnes for native kg data.

``sector-sections.json`` is the authoritative browser correspondence. EXIOBASE
codes were matched exactly to the 163 labels in the official ``exio3class.xlsx``
industry sheet (source URL and SHA-256 recorded). The native two-digit divisions
roll up to NACE Rev. 1.1 sections; OECD's code prefixes roll up to ISIC Rev. 4.
Do not compare the letters across revisions without a verified concordance.
When a reading has a verified correspondence, add it and check that every
industry is assigned once. Otherwise retain Whole economy and hide the
correspondence download for selections without a mapping. CSV exports follow the active chart/table.

The Excel file is generated from that JSON by ``build_sector_correspondence.mjs``
using ``@oai/artifact-tool``. Run it in a temporary workspace with the library
available, passing the JSON file and an output directory as arguments; inspect
its rendered sheets before copying the XLSX into ``_static/data/economy``.

For a new release, check its native row labels, units, geography and price
basis. Do not sum every factor row automatically, include imports in value
added, apply GWP twice to already characterised gases, infer aggregate-region
population, substitute a different year, or turn absent extensions into zeros.
Whole-economy GHG includes producer accounts plus observed direct final-demand
EY. Producer sector accounts remain separate from EY. Consumption-based
accounts need a separate footprint calculation. National USEEIO and BEA models
are retained in the snapshot archive for later work, outside the MRIO browser.

EXIOBASE 2024 has negligible product taxes and a zero final-demand tax bridge,
so its GDP is labelled an estimate. The 2022 and 2023 source tax bridges are
retained and added to value added. OECD includes the published TLS bridge for
intermediate and final demand; ADB uses its original worksheet tax row. BEA
subtracts the positive Va subsidy row and sums the signed Vc product-tax rows
on total supply, without adding final-use taxes again. EMERGING explicitly
uses native value added as a labelled GDP proxy; other readings without a
reviewed proxy remain unavailable until their accounting bridge is verified.

The publisher writes only aggregated indicator vectors and recipe metadata.
Never commit local input paths, raw V/E/Y/Z blocks or coefficients. Keep source
licensing and attribution specific to each release. Source checksums in the
snapshot identify the input vintage; inspect results before updating the preview.

For OneDrive inputs, work on one database at a time. After extracting and
validating its indicators, use Finder's **Free Up Space** and verify that no
source blocks remain locally allocated. Do not delete cloud originals.

remains available from the verified source tax bridge.

native combustion CH4 row, characterised at EDGAR-compatible AR5 GWP100 28;
the scope is stated explicitly.

Complete EXIOBASE refresh
-------------------------

Use the resumable pipeline in ``doc/scripts/exiobase``. Its default staging
directory is Git-ignored ``Output/exiobase-browser``; a temporary location can
be selected with ``MARIO_EXIOBASE_STAGE``::

   export MARIO_EXIOBASE_STAGE=/tmp/mario-exiobase
   python doc/scripts/exiobase/collect.py --workers 3 --refresh-inventory
   python doc/scripts/exiobase/collect_sut.py --workers 3
   python doc/scripts/fetch_world_bank.py --start 1995 --end 2024 \
     --output "$MARIO_EXIOBASE_STAGE/world-bank-ready.json"

The monetary collector uses MARIO numeric readers and canonical axes on
original V/VY/E/EY members, and inventories every native set/unit file. It does
not load transaction matrices or calculate inverses. HTTP ranges and ZIP
member CRCs are checked; each selected member receives a SHA-256 hash. The
published archive checksum identifies the input, but is not recalculated on
unread archive bytes. A member cache checks the original CRC and size before
reuse. Requests are paced, with backoff on HTTP 429. Cached readings are reused
only when their published archive checksum matches.

Official 3.8.2 archives retain a stale v3.81 metadata field while naming
``exio382_ntnu``. The parser recognises this specific source inconsistency;
genuine 3.8.1 metadata is not relabelled. SUT income is read independently from
the original Va and checked against every corresponding IOT activity value.
SUT native values are EUR; IOT values are million EUR. The exact same
release/year IOT supplies satellite accounts and the final-use tax bridge.

For Hybrid, obtain the official files with MARIO's downloader, then run::

   python doc/scripts/exiobase/hybrid.py --path /local/official-hybrid
   python doc/scripts/exiobase/hybrid_mapping.py \
     --classification /local/official-hybrid/Classifications_v_3_3_18.xlsx

HIOT is parsed fully with all supported extensions and its monetary income
total is checked against the original workbook. Every required source file is
checked against its published MD5 and independently hashed with SHA-256.
The product correspondence uses original codes from ``Correspondence_products``;
every constituent CPA section is checked. Existing verified HSUT is retained.

Prepare and review the public files separately::

   python doc/scripts/exiobase/publish.py
   node doc/scripts/exiobase/build_sets.mjs "$MARIO_EXIOBASE_STAGE/catalogue-build.json"
   node doc/scripts/build_sector_correspondence.mjs \
     "$MARIO_EXIOBASE_STAGE/sections-ready.json" "$MARIO_EXIOBASE_STAGE/correspondence"
   python doc/scripts/exiobase/publish.py --publish

The workbook builders require ``@oai/artifact-tool`` in the execution workspace.
Inspect their rendered sheets before publication, and copy the verified sector
workbook to ``doc/source/_static/data/economy/sector-correspondence.xlsx``.
There are 38 new native set inventories plus the existing Hybrid HSUT inventory.
Years share an inventory only when all native labels, units and regional set
associations agree. Changes in satellite rows produce distinct downloads;
region/sector counts are still compactly grouped in parser cards and guides.
Each workbook retains the separately checked source years and archive identities.

Remove the staging ``member-cache`` and any temporary raw Hybrid inputs after
verification. No OneDrive source needs to be hydrated by the remote monetary
pipeline. Never delete cloud originals.


Database explorer navigation and selection
------------------------------------------

The Resources hero contains a Database explorer dropdown linking to three
peer pages: ``data-explorer/scope`` (Classifications),
``data-explorer/compare`` (Compare databases) and ``data-explorer/analyses`` (Analyses).
They use that order in both the dropdown and full-width page tabs.
Electricity activates Analyses. The Resources landing and legacy
``resources/research`` URL open Classifications; research anchors retain their
destination in ``projects_publications``. Existing coverage anchors redirect
on both initial page load and hash changes. The wide column remains limited
to this section.

Years accept explicit subsets or All. Countries accept explicit subsets or
World: this sums every native database region, including aggregate regions,
exactly once. A missing regional value makes the total unavailable. World is
available only for global MRIO families, not national BEA/USEEIO models. World
per-capita values divide the total by same-year WDI WLD population; they never
sum country per-capita ratios. The reference uses published WLD GDP/per-capita
series, stored separately from individual countries in ``world-bank.json``.

Aggregate choices use the family, complete native geography and region code
as identity. Identical EXIOBASE monetary ixi/pxp geographies share choices;
different regional systems and unrelated RoW definitions never match by name.
GHG is selectable only when every selected reading provides the required
verified extension. A change to an unsupported reading resets GHG to Value added.

Comparisons use expandable family/version checkboxes: latest releases are
selected in charts by default, all versions in tables, and explicit user
selections take precedence in both. Numeric release identifiers are ordered
numerically; incomparable named variants use their latest available source
year. Same-release ixi/pxp systems remain independently selectable. OECD ICIO Regular and Extended are coexisting variants: both are selected by default when comparing database families.

Applicable World Bank (GDP) and EDGAR (GHG) references are always included;
they have no selection checkboxes. Scatterplots use short horizontal dash
markers at each year, without connecting lines. Annual bars show distinct,
muted diamond references. Single-year comparisons show one full-width horizontal
reference line per country, independent of the selected database releases;
the legend lists only database families and reference sources. Invisible hover
anchors expose that same reference value when hovering a bar. Legend groups
toggle the line and its hover data together. A unified
hover compares the selected series for one year. Its pixel tolerance adapts to
width and zoom so a missing year never borrows an adjacent-year value. CSV
exports retain country, version, units, table format, system, year and provenance
for the selected subset;
``value`` / ``unit`` use the display scale, while ``raw_value`` / ``raw_unit``
preserve the unscaled observation.

On narrow screens, Plotly charts resize to the available width.
Source lists collapse for comparisons; single-reading provenance remains visible.
Disabled and single-option controls fade. Both maps draw a separate visible
selection layer above the border mesh.


Interactive figures and scope overview
-------------------------------------

The documentation's existing Plotly runtime powers charts, including legend
click/double-click visibility, drag zoom, pan, PNG export and double-click
axis autoscaling. ``economy-charts.js`` holds display scaling and figure logic;
``economy-model.js`` retains selection and numerical calculations. One
database family uses bars for one reading combination across several years, and for any selection
in one year. Scatter is used when both reading combinations and years are
multiple. A combination is Units + Version + Table format + System, so ixi
and pxp of the same release are two readings, not one. Annual single-reading
bars retain reference diamonds.
Single-year charts with references retain vertical bars so the reference is a
horizontal line across the plot. Comparisons keep their annual scatter /
single-year bar views.

Version facets, opened with the arrow beside a database, are derived from recipes. EXIOBASE separates Units (Monetary /
Hybrid), Version (release), Table format (IOT / SUT) and System (ixi / pxp).
The Hybrid HIOT parser uses a product axis, so its system is pxp. System is inapplicable
to SUTs; System choices only filter IOTs when both formats are selected. Facets accept
subsets; dependent choices are trimmed to valid combinations, and one-option
controls fade. Other families show their applicable fields. Colours identify
database families. With one family in the chart, System determines marker shape
(circle ixi, square pxp, diamond SUT) and Hybrid uses open markers; with several
families, shapes distinguish readings. The map and the MARIO Python example need
one reading (one version and one year); otherwise the map is disabled and a hint
beside the example explains how to enable it. GDP and
GHG choices require verified availability in every selected reading, except explicitly reviewed source errors, which remain gaps alongside valid years.

Shared display scales cover database and reference observations; monetary
figures use thousands, millions, billions or trillions of current USD, and GHG
figures use t / kt / Mt / Gt CO2eq. Per-capita GHG remains tonnes per person.
Numeric ticks adapt to zoom. Plotly's container height is explicit to avoid
responsive 100-percent-height collapse after switching views.

``database-scope.js`` builds the MRIO overview from parsed set counts in the
public catalogue. The x axis counts sectors / activities / commodities, the y
axis counts native regions, including aggregates. Family determines shape;
colour describes whether environmental accounts were loaded in that reading.
Repeated years and releases at the same size are combined in the hover; SUT
activity and commodity classifications remain identified. National models
are excluded. Only classification metadata is used, including the existing
public EORA26 set inventory; restricted EORA numerical results remain
local. Geography groups EXIOBASE monetary releases as Monetary - All versions.

     tests/docs/test_economy_charts.cjs tests/docs/test_database_scope.cjs

Dynamic country / region options
--------------------------------

``countryOptions`` in ``economy-model.js`` derives native regions from active
family/version/year readings, rather than all years of the selected versions.
Comparison choices are the union of the regions in those active readings;
reference geography never expands the list. Rows for absent countries remain
unavailable in the other selected databases. Aggregate identifiers retain their
family and exact native geography, so a RoW from a different regional definition
cannot silently replace the user's selection. Valid country subsets survive a
filter change; invalid choices are dropped. With no surviving choice, global
readings return to World and national models return to their first native region.
An empty database selection disables the country picker with no choices.


GDP/CO2 proxies and GHG boundary audit (2026-10-09)
-------------------------------------------------

EMERGING GDP is explicitly a presentation proxy: the sum of native ``va``,
without an invented product-tax bridge. All twelve verified economic readings
publish that proxy. Eleven standard readings also publish the seven fuel CO2
accounts as an incomplete GHG proxy. CO2 has GWP 1 under AR5 and AR6; native
Mt CO2eq is scaled by 1e6 to tonnes. EMERGING-E uses the same-year EMERGING 2.2 CO2 companion projected onto
its native sectors, with electricity allocated by fuel; these are modelled
emissions rather than a separate observed extension.
These caveats are visible beneath the plot in either browser mode and retained
in CSV/Python exports. Rebuild from verified economic snapshots and matching
small CO2 companions without re-reading economic matrices::

   python doc/scripts/emerging/refresh_indicators.py --stage Output/emerging-browser
   python doc/scripts/emerging/publish.py --stage Output/emerging-browser --publish

The refresh requires the prior full MARIO flow and VA checks, unchanged SHA-256
of each CO2 companion, native axis ordering and exact native fuel units. It
independently reconciles every characterised sector cell to the raw fuel sum.

Whole-economy GHG now includes E/Ea/Ec plus EY where actually supplied. Sector
values remain producer accounts; EY is never allocated to production sectors.
Python exports calculate the two separately then add region totals once;
breakdown exports include a separate direct-final-demand row. Missing EY in
EMERGING/USEEIO remains missing, rather than an observed zero.

All mass conversions and factor selections are checked against the native
unit metadata. EXIOBASE monetary mass-reported gases are recharacterised
with EDGAR-compatible AR5 GWP100 (CO2 1; CH4 28; N2O 265; SF6 23500;
NF3 16100 where present). This matches EDGAR's methane factor, although
AR5 also tabulates a fossil-methane value of 30. Already-characterised HFC/PFC
retain their source CO2-equivalents; the original IPCC basis is not independently
verified. Hybrid GHG is an AR5-characterised three-gas subtotal; F-gases are missing
and extension overlap remains unresolved. ADB and EDGAR retain source AR5 GWP100.
USEEIO retains native workbook C factors, including methane 27.9, and its
import-related commodity boundary. No uniform gas coverage or territorial
equivalence is claimed. EDGAR references remain unchanged published cells.

For EXIOBASE 3.11.2 ixi in 2023, world E alone is 44.729 Gt; EY is 4.556 Gt;
E+EY is 49.285 Gt, against EDGAR's published 52.999 Gt. The apparent gap falls
from 15.6% to 7.0%. US totals move from 4.903 to 5.832 Gt, against 5.863 Gt
(gap 16.4% to 0.5%). This checks the display boundary, rather than proving the
remaining difference has one cause. Source vintages, residence/territory,
native geographic groupings, gas coverage and GWP mixtures still differ.


Bulk filter selection
---------------------

Multi-select pickers expose Select all and Unselect all. Compare databases
places these actions beside the Databases and versions legend, in normal-weight
text. Selecting all there explicitly opts into every version of every family;
otherwise latest-release defaults remain unchanged. World continues to mean
the sum of each native MRIO region once, including aggregates; Country / region
Select all chooses that World total where available.

Sector aggregates apply to value added and GHG. For GHG the sector picker also
offers Households (direct EY emissions) in a separate Final demand group; it
needs no sector mapping, so it stays available when families lack a common
classification. All sections plus Households equal the whole-economy total.
EDGAR references remain whole-economy only.

Years default to the 20 most recent available years before the current calendar
year, so publisher forecasts for the current and later years are opt-in. The
picker label shows the period; Last 5 / Last 10 / Last 20 and Select all
consider every available year.

Unselect all preserves an explicit empty selection for years, country/region,
sectors and reading facets. It never silently selects a default. Empty source
filters preserve country preferences until valid readings return; invalid
nonempty country subsets still use the established fallback. Bulk commands
follow the currently eligible options and retain single-option disabled states.
GWP harmonisation remains pending; this UI update does not change indicator values.

Country scope and classifications
---------------------------------

``country-scope.json`` holds native set metadata by country and feeds
``build_sectoral_scope.py``. The Focus on a country view that displayed it was
removed; Compare databases and the Classifications page cover its uses.
The generator reads existing parsed set JSON and the supplied EXIOBASE
concordance workbooks; it never hydrates or parses economic matrices::

   python doc/scripts/build_country_scope.py --concordances /local/concordances

``country-model.js`` keeps global region counts separate from the selected
country's native economic memberships. SUT activities and commodities remain
separate. EORA's numerical results remain local.

Official classification revisions are separate. The NACE Rev. 1.1 hierarchy
is available through four digits, but current activity mappings are verified
only at section level. The CPA 2002 product lookup uses explicit source
correspondences and the EXIOBASE 2-to-3 code/name bridge, keeping incomplete
coverage visible. Neither a shared parent nor a missing correspondence
establishes fine-code membership or absence. Links do not disaggregate values.

``build_classification_workbook.mjs`` exports the correspondence and hierarchy
with text identifiers, source references and relation types. Run it in a
temporary workspace with ``@oai/artifact-tool`` available, passing the scope
JSON and output directory. Inspect the workbook and previews before copying
``classification-correspondence.xlsx`` into ``_static/data/economy``.

Country model and chart verification::

Source-only database coverage
-----------------------------

``external_profiles.json`` is separate from the parser-derived catalogue.
Only source-verified metadata belongs here; it does not create an indicator
reading or imply that MARIO can parse the source. Each profile supplies native
identifiers, explicit geography, source vintage, base year, licence and the

Inventory Open CEDA without reading its numerical factor cells::

   python doc/scripts/build_external_profiles.py --open-ceda /local/open-ceda.xlsx --data doc/source/_static/data --output /tmp/ceda-scope

Review the extracted profile and curate the registry; the extractor preserves
other source-only profiles on refresh. Generate the metadata-only set workbook
with ``build_external_profile_workbook.mjs`` in a temporary workspace containing
``@oai/artifact-tool``. Open CEDA 2025 (released 11 November 2025) has base year
2023, 148 individually reported countries plus ROW and 400 native BEA-based
sectors, unchanged from 2024; its factors use IPCC AR6 GWP100. The extractor
reads both the 2024 single-sheet layout and the 2025 Cover/GHG_t_Raw layout. Its
alphanumeric native codes are not assumed to be NAICS. Source metadata and
its derived workbook use the source's CC BY-SA 4.0 attribution.

WIOD 2016 multiregional inventory
--------------------------------

``wiod/collect.py`` reads 44 local XLSB files through the public MARIO parser:
15 current-price IOTs and 15 international SUTs (2000–2014), plus 14 PYP IOTs
(2001–2014). It observes the original VA/TXSP rows during parsing and independently
reconciles every country GDP, without inverses or source-matrix exports.
``wiod/publish.py`` groups equal native sets into three downloadable inventories;
``wiod/build_sets.mjs`` authors and checks their Excel workbooks.

Current-price readings attach the 16 local socioeconomic accounts; PYP readings
do not mix these current-year monetary extensions into previous-year accounts.
No local WIOD environmental file supplies GHG. International SUT ROW imports are
external factors, so only the IOTs expose World totals. PYP values retain
previous-year USD and omit current-price World Bank references.

The international SUT parser preserves signed published factor rows on final
uses in VY. GDP includes TXSP on intermediate and final uses; adjustment, margin
and ROW-import factor rows are excluded. National WIOD files are out of scope.


FIGARO complete current API inventory
--------------------------------------

The official Eurostat dataflows cover 2010–2024. ``figaro/collect_all.py``
downloads normalized, resumable API caches; ``figaro/run_all.py`` runs two
bounded workers from that inventory. All 45 readings are full public MARIO
parses with ``calc_all=False``: 15 IOT pxp, 15 IOT ixi and 15 SUT. Existing
product tables were refreshed to the same current API dissemination as the
new systems and years. Each source CSV has a SHA-256 and API update date.

All have 50 regions (49 individual countries and RoW), six factors and five
final-demand categories. IOTs have 64 native sectors; SUTs have 64 NACE Rev.2
activities and 64 CPA 2.1 commodities. No environmental accounts are loaded.
Identical native sets share three Excel inventories across years. ``ip1``–
``ip4`` and corresponding use/supply suffixes partition years. FIGARO has no
release/version filter: years, table formats and IOT systems identify readings.

GDP sums D1, D29X39 and B2A3G, then adds D21X31 on intermediate and final uses.
Signed taxes remain signed. Every country total independently reconciles to
the original factor/use observations. The source-currency snapshots retain
EUR; the browser converts to same-year current USD. FIGARO compilation uses
national accounts and World Bank world GDP, so the comparison is not an
independent accuracy test.

Current supply dataflows use one ``geo`` dimension: MARIO places domestic
production in the same region on both supply axes. Use tables retain origin
and destination. The normalized caches support both this layout and the
legacy regional CSV layout. ``figaro_csv`` reads the final-use tax bridge from
the matching IOT or SUT Use cache, which the native matrices omit.

Native section mappings are independent: NACE activities and CPA commodities
remain available in SUT country scope. They are not fine-code allocation
weights. Source caches are returned to OneDrive online-only after each
completed year's three parses.


The Environmentally extended preset applies to individual readings, not entire
families. It selects snapshots with loaded GHG observations, constraining
version, year and geography options to that pool. ADB years without emissions
are excluded; EMERGING-E is included with its explicitly documented
projection from the same-year EMERGING 2.2 CO2 companion. Missing selected years remain missing; no year is
substituted. The preset does not harmonise GWP bases or promote CO2-only proxies
to full GHG coverage. Select all or a second click clears the preset; manual
comparisons including readings without emissions still disable GHG.


EXIOBASE source-extension quality review
----------------------------------------

GHG totals are unavailable for monetary EXIOBASE 3.10.1 in 2022–2024 and
3.10.2 in 2023–2024, in both ixi and pxp. Raw archive members were independently
reread and their CRC/SHA256 matched the original extraction. The 3.10.1 source
contains anomalous non-combustion extensions; the 3.10.2 changelog documents a
correction for changed source formats. Both releases have all combustion rows
and final-demand combustion emissions zero in 2023–2024, as also reported in
the public EXIOBASE issue tracker. No years or releases are substituted.

``annotate_source_quality`` preserves these explicit reviewed exclusions across
republication. Original numerical vectors remain auditable, with
``ghg_usable=false``. The model, lazy manifest, CSV and Python selector all honor
that flag. Mixed-year selections retain valid observations and show gaps;
selections containing only defective years disable GHG. GDP and value added
remain available. ``exiobase-ghg-audit.json`` records the independent native-row
contributions and control readings. Sources:
https://zenodo.org/records/20051562 and
https://github.com/EXIOBASE/exiobase-bugs-public/issues/1.

GLORIA reviewed local extraction
--------------------------------

``gloria/collect.py`` reads each local year with MARIO's native block readers,
using float64 for Va/Vc/Ea/Ec/EY and the signed valuation summaries. Full
transactions and IO inverses are not loaded for these indicators. The source
archives are restored online-only after each successful validation. This batch
includes all forty locally verified economic readings from 1990 to 2029
(2024–2029 are publisher forecasts);
satellite-only years are not treated as complete economic datasets.

``gloria/publish_years.py`` publishes validated readings with a single native-set
profile after comparing labels, units and regional memberships. The existing
2024 profile identifier stays stable; its year list includes 1990–2029.
``gloria/build_sets.mjs`` updates the shared Excel's title and source note while
preserving all native records. Publication reuses the common indicator publisher
and updates GLORIA's country, sectoral and extension scope year metadata. No source
matrices are embedded and EORA remains local. GLORIA has 164 source regions
(159 individual countries, four rest-of-world aggregates and the historical
DYE source region), 120 activities, 120 commodities, six factors, six final-demand
categories and 5,588 loaded emission satellite rows. SDS resolves to South
Sudan (SSD) using the source README. DYE is retained, with zero 2024 vectors.

Value added sums six signed factor rows. The native EDGAR-consistent GHG total
is scaled from kt to t, including observed EY once. Independent checks of
2001 and 2024 native rows recover AR5 GWP100 factors for CO2, CH4, N2O, SF6
and NF3; the relative L2 residual of the activity-cell fit is below 1e-8
in 2001 and about 0.15% in 2024. Individual fluorinated-gas factors are not all identifiable,
and the original CO2eq total is retained. The release notes trace the
EDGAR-consistent block to EDGAR 7.0 but do not state a GWP convention.
GDP adds source-signed product taxes and subsidies on intermediate and final commodity uses to basic-price value added. The
README ISIC Rev. 4 binary concordance combines Other services into S+T rather
than double-counting it or assigning arbitrary weights.


GLORIA GDP product-tax bridge
----------------------------

``gloria/product_taxes.py`` streams Markup004 (product taxes) and Markup005
(signed subsidies) through MARIO's GLORIA resource/batch reader. Commodity-row
intermediate uses are grouped by destination activity region; final uses are
grouped by destination final-demand region. Activity-row and supply-side tax
blocks are verified as zero. Source units are thousand current USD. Subsidies
are already negative and are added once. Product taxes are separate from the
D.29/D.39 production-tax components already included in basic-price value added.

``gloria/gdp-bridge.json`` retains regional totals, exact member names/CRCs and
an independent world income/expenditure check using all five final-demand
valuations. Re-running ``gloria/publish.py`` reapplies this bridge; the generic
local runner also reconstructs it from original source valuations. The short
MARIO download explains the two additional valuations and destination-region
aggregation. Source matrices are never published.

Annual checks are retained in ``gloria/gdp-bridge-<year>.json`` for each
additional reading (1990–2023 and 2025). Archive member
identities and precision accompany each shared-profile reading. Cached valuation
summaries are reused only when the member name, size and CRC still match.

To collect further locally available years, prepare publication, update the
workbook and then publish::

   python doc/scripts/gloria/collect.py --root /local/GLORIA --years 2001 2002 2003 2004 2005 2006 2007 2008 2009 2010 2011 2012 2013 2014 2015 2016 \
     --stage /local/gloria-stage --evict-command /local/evict_foundation
   python doc/scripts/gloria/publish_years.py --stage /local/gloria-stage
   MARIO_GLORIA_SETS_INPUT=doc/source/_static/data/database_profiles/gloria-060-2024-sut.xlsx \
     node doc/scripts/gloria/build_sets.mjs /local/gloria-stage/workbook
   python doc/scripts/gloria/publish_years.py --stage /local/gloria-stage --publish

The eviction helper calls the operating system's cloud-file eviction API on the
two exact source archives and checks that their allocated disk blocks are zero.
It never removes source files from OneDrive. The shared README is evicted after
all selected years have been processed. ``gloria/sectoral.py`` snapshots its
published section anchors and historical concordance first. Sectoral coverage
then uses metadata snapshots without a live nxbase or source-archive dependency.

For v060/2024 the income total is approximately 112.992 trillion USD. The
expenditure-side check differs by 764.106 million USD (0.000676%); this residual
is recorded, not distributed across regions or hidden by forcing equality.
The source-check tolerance is 0.001% at world level.

The 2023 income/expenditure residual is 203.256 billion USD (0.186%).
An independent direct CSV reading of Va and all five Y valuations reproduces
the discrepancy, with matching CRCs and zero Vc. GDP retains the unadjusted
income-side calculation; the note identifies the source residual.
``gloria/audit_accounting.py`` reproduces this check. Exceeding the 0.001%
balance tolerance requires these independent source checks, and records
``identity_status=independently_reproduced_source_residual`` instead of claiming
the accounting identity passed. No tolerance is silently widened.

The equivalent 2022 independent check records a 25.377 billion USD residual
(0.024%). Both annual GDP vectors and their source tax bridges are retained
without balancing. The concise quality note is shown when GDP is selected,
including multi-year selections, and is carried into CSV notes.
